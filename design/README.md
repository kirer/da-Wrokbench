# DSH 部门研发工作台 · 高保真 UI 交付说明

> 产品：DeepSeek Harness（DSH）桌面插件 · 第一版聚焦「迭代 → 需求 → 评审/排期 → 设计」。
> 画幅：桌面端 1440×900，右栏 360–420px（本稿 388px）。中文界面，浅色 / 深色两套。
> 视觉：冷净的工程感 —— 中性冷灰为底、低饱和蓝为主色、编号/版本用等宽、圆角 6–8、细边框、克制阴影。参照 DSH 原生深色外观（近黑 #151517）。

---

> **产品定位（2026-11-22 校正）**：这是 **DSH 的插件**，不是独立 App。最左的窄栏（deepseek HARNESS / 新会话 / 插件列表 / 工作区）和中间的会话都是 **DSH 原生**的，不改造；我们只在左栏放一个高亮入口「研发工作台 · 插件」。插件自己的界面 = 顶部横向 tab（迭代 / 我的工作台 / 技能库 / 设置）+ 页面里的卡片，以及会话右侧的「需求 / 设计工作台」面板。开发 / 测试工作台仅留入口。

> **DSH 原生区域一律占位**：左侧栏（除「研发工作台」入口）、聊天会话区、右侧「设计台」栏（工作区文件 / 上下文 / 终端 / 浏览器…）都只画成**明确标注的占位块**，不细化——避免开发智能体把它们当成要实现的东西。**需求工作台、设计工作台两屏也改成占位**（DSH 右栏形态）。本插件的真稿 = 插件页面本身。填充按钮统一**蓝底白字**。新建迭代、新建需求都用**弹窗**。

## 二、设计系统（详见 `design-system.html`）

### 颜色（角色化，深色默认 / 浅色映射同一角色）
- 背景 `--bg` #151517 · 左栏 `--bg-elev` #191919 · 右栏 `--panel` #1b1b1e · 卡片 `--surface` #232326 · 抬升 `--surface-2/3`
- 边框 `--line` #2b2b30 → `--line-2/--line-3` 逐级加强
- 文字 `--text` #ededef / `--text-2` #adb0b8 / `--text-3` #9a9aa2（≥4.5:1）/ `--text-4` 仅装饰
- 主色 `--primary` #6f9bf0（低饱和蓝）；状态语义 `--st-idle/prog/done/block/na/draft/warn`，均按深/浅分别提亮或压深以过 4.5:1
- 状态色：未开始(灰) · 进行中(蓝) · 已完成(绿) · 阻塞(红) · 不涉及(灰虚线) · 仅本地草稿(紫虚线) · 待评审(琥珀)

### 字体与字号
- 中文：`"Inter", -apple-system, "PingFang SC", "HarmonyOS Sans SC", "MiSans", "Microsoft YaHei", system-ui`
- 等宽（编号 / 版本 / 代码 / 日期）：`"JetBrains Mono", "SF Mono", ui-monospace`
- 阶梯 12 / 13 / 14 / 16 / 19 / 22 / 28（比例≈1.15–1.25，密集工具型）；可读下限 12px

### 间距 / 圆角 / 阴影
- 间距 4 / 8 栅格（2·4·6·8·12·16·20·24·32）
- 圆角 4 / 6 / 8 / 10 / 999（6–8 为主）
- 深色靠表面明度分层、几乎不用阴影；浅色才用三档柔影

### 组件（都已出样张）
按钮（主/次/危险/文字 · 大/小/图标/禁用/加载）、输入框（默认/聚焦/错误/下拉/日期/多行/搜索）、分段筛选、表格、卡片、**状态 chip（图标+文字，不只靠颜色）**、**阶段矩阵**（完整 + 表格行内紧凑两版）、头像/指派、标签页、右栏面板、空/加载/错误/无权限态、Toast、Mock 横幅、确认弹窗、版本 diff、文件选择器、开关。

> 可访问性：正文 ≥4.5:1、大字/图标 ≥3:1；状态 chip 同时带几何图标（○ ◐ ✓ ! — ◇ ◷）+ 文字，色盲可辨；焦点态 2px 主色光环；点击热区 ≥ 24（图标按钮可更大）。

## 三、全局信息架构

- **左栏 = DSH 原生**：deepseek HARNESS、新会话、插件市场 / 自动化任务 / 上下文洞察 / 记忆系统、工作区列表、底部身份。和我们无关，不改。唯一改动是加一个高亮入口 **「研发工作台 · 插件」**。
- **插件内部导航**：页面顶部的横向 tab —— 迭代 / 我的工作台 / 技能库 / 设置（不再用左栏做插件导航）。
- **中间**：主页面内容是插件页面（迭代/需求/技能等）；打开需求/设计会话时，中间是 DSH 会话（保持原生风格，必要时占位）。
- **右侧工作台**：随会话打开的插件面板（需求工作台 / 设计工作台）；开发/测试工作台仅留入口（Phase 2/3）。
- **表达方式**：能用卡片+连线的不用表格长文。迭代详情的需求是「脑图卡片」，需求全量是「卡片墙」，后面互相链接。
- **沉淀分级**：草稿=仅本地（紫虚线 + `仅本地` 徽标）；已提交 / 已交付=服务端（绿/蓝徽标）。全量卡片只展示已提交/已交付版本。

## 四、逐页说明

### 1. 登录与首次使用 `login.html`
- **目标**：钉钉/Mock 登录，并引出「选职能+平台 → 选顶级文件夹」首次流程。
- **布局**：左右分栏。左=品牌 + 4 步产品流程；右=登录卡。
- **关键组件**：Mock 模式横幅、测试用户单选列表（张三/李四/王五/赵六/钱七/周九，带角色与多平台示例）、主按钮「以身份进入」、钉钉扫码、首次使用提示。
- **状态（页内已示意）**：未登录（默认）/ 登录中（spinner）/ 失败（网络异常）/ 权限不足（未开通）/ Mock 提示。
- **交互**：点用户行切换选中；「以身份进入」→ 迭代列表；正式/ Mock 界面一致，只换 Provider。

### 2. 迭代列表 `iterations.html`
- **目标**：扫一眼所有迭代的阶段、进度、风险；按「我参与的/进行中/已封板」筛选；新建迭代。
- **布局**：顶栏搜索筛选 + 页面标题 + 4 个 KPI + 筛选段 + 迭代表。**只保留一个「新建迭代」主按钮**（去掉了「我的工作台」）。
- **关键组件**：KPI 小卡、阶段 chip、进度条、负责人头像、风险 chip。
- **交互**：**整行可点**（连编号格一起）→ 迭代详情；「新建迭代」**弹窗**填编号/名称/负责人 → 创建，不再跳错页。
- **状态**：默认 / 加载 / 空 / 错误 / 无权限。

### 3. 迭代详情 `iteration-detail.html`
- **目标**：看懂迭代节奏与卡点，尤其「设计可与需求/开发并行」。
- **布局**：头部 → 左主列（阶段时间轴 + 需求「脑图卡片」）+ 右列（活动日志、范围）。**设计任务区块已去掉**。
- **关键组件**：时间轴（设计轨道与需求/开发重叠）、**需求卡片（脑图/流程图风）**——每张卡是一条脉络，标题进「需求全量」，右侧小卡链到 总述 / 原型 / 设计稿 / 工作台；右列活动日志时间线。
- **设计并行的表达**：顶部「设计与开发轨道重叠」；设计未指派不阻塞；只有明确等待设计时才显示「等待设计」；晚交付标「设计已更新」。不再出现 designMode 或「设计先行 / 并行」模式名。
- **状态**：无需求 / 设计未指派 / 设计并行 / 范围锁定。

### 4. 新建需求（弹窗，不单独成屏）
- 在迭代详情点「新建需求」弹出：填标题即可，其余进工作台再补；草稿只存本地。与「新建迭代」一样用 `:target` 弹窗，可点开。

### 5. 需求工作台（占位）`requirement-workbench.html`
- 按评审意见改为**占位**：左栏 DSH 占位、中间 DSH 会话区占位（**没有标题栏**）、右侧为 DSH「设计台」右栏形态的占位块，并注明「需求 / 设计工作台将**基于 dsh-design-studio 改造**」。

### 6. 需求全量页 `requirement-full.html`
- **目标**：需求沉淀全部**卡片化**，每块可点开——不是长文档。
- **卡片结构（按评审意见合并）**：总述（跨两列）／原型（**并入版本历史**）／设计稿（**加人员 王五 + 打开链接，并入设计组件**）；**各端拆成每端一张卡**：服务端（**并入接口文档**）、Web、iOS、安卓、鸿蒙、测试（**并入 Bug**）。
- **布局**：紧凑头部 + 两列卡片墙 + 平台卡三列网格（各端不再单加小标题，直接上卡片）。
- **状态**：无设计 / 设计未交付 / 设计已更新 / 历史版本。

### 7. 设计工作台（占位）`design-workbench.html`
- 同需求工作台，改为**占位**：左栏 / 聊天（无标题栏）/ 右侧 DSH「设计台」都占位，注明基于 dsh-design-studio 改造。

### 8. 技能库（最小版）`skill-library.html`
- **目标**：一眼看懂技能的名称/版本/适用角色/状态/启用停用。
- **布局**：左技能列表（master）+ 右详情（描述 / changelog / 内容预览 / 版本历史 / 兼容性）。
- **关键组件**：技能行（版本徽标、状态 chip）、启用开关、changelog、SKILL.md 预览、版本历史（固定版本）；个人上传入口灰置「Phase 2」。
- **状态**：空 / 加载 / 已废弃 / 无权限（底部状态条）。

### 9. 技能管理（P1）`skill-admin.html`
- **目标**：审核队列、上传、角色技能包、使用统计。
- **关键组件**：待审表（通过/打回）、**「上传技能」弹窗**（4 步向导 + 校验结果，不再占页面）、角色包卡（强制/推荐）、使用统计条形。
- **状态**：校验失败 / 待审 / 通过 / 打回。

### 10. 我的工作台（P1）`my-workbench.html`
- **目标**：只看与我有关的，**需求 / 设计任务 / 待办合并成一份清单**，按需求去重——一行看完「这条需求里我是谁（产品/设计/系统）、当前状态、要我做什么」。
- **布局**：标题摘要 + **一条统计条**（本月完成 / 进行中 / 待我处理 / 按时交付）+ 筛选（全部 / 需求 / 设计任务 / 待我处理）+ 单列工作清单。
- **状态**：空 / 只有设计任务 / 加载 / 多身份。

### 11. 设置（P1）`settings.html`
- **目标**：身份与平台（多选）、顶级文件夹（可写校验）、认证模式（Mock/钉钉）、通知偏好、技能更新策略。
- **关键组件**：多选勾选、路径框（可写徽标）、认证单选卡 + Mock 提示、开关行、策略下拉。
- **状态**：Mock/正式切换提示 / 路径无效 / 保存成功 / 无权限。

### 12. 通知中心 / Mock 模拟器（P1）`notifications.html`
- **目标**：指派 / 变更 / 交付 / 系统消息；第一版带 Mock 通知模拟器。
- **关键组件**：模拟器（模拟指派/变更/交付/系统）、筛选段、通知行（类型图标、未读圆点+底色、时间、动作）。
- **状态**：空 / 未读 / Mock 通知 / 加载。

## 五、关键状态矩阵（三条主线）

| 维度 | 取值与视觉 |
|---|---|
| 需求生命周期 | 创建中 / 待评审(琥珀) / 已排期(蓝) / 进行中(蓝) / 待测试 / 测试中 / 已完成(绿) / 已封板(绿) + 异常(阻塞红) |
| 阶段矩阵（动态） | 需求 · 设计 · 该需求实际涉及的平台（按组分组，服务端/前端/客户端可多团队） · 测试；每个平台一条 chip（未开始/进行中/已完成/阻塞/不涉及），平台多时汇总 + 展开，不涉及折叠 |
| 设计状态 | 无需设计 / 待认领 / 已指派 / 设计中 / 已交付 / 待修改 / 设计已更新；认领/指派由会话 skill 完成 |
| 沉淀分级 | 草稿（仅本地，紫虚线）/ 已提交（绿）/ 已交付（蓝）；全量页只显示后两者 |

## 六、交给前端实现时的建议

1. 先把 `tokens.css` 的变量接进项目主题（DSH 若已有主题变量，映射同角色即可）。
2. `app.css` 里的组件类可原地复用，或按团队框架拆成 Button / Chip / Matrix / Table / Panel 等组件；`状态 chip` 与 `阶段矩阵` 建议做成受控组件。
3. 图标用 `icons.svg` 的 symbol；换成项目 icon 库时保持 24 网格、1.75 线宽、圆角端点。
4. 状态 chip 的「图标 + 文字」不要退化成纯色块，保证色盲可辨。
5. 深/浅两套都要回归对比度；主色只用于关键操作与少量点缀。

> 说明：示例数据（迭代 2026-S11、需求 S11-001~007、用户张三/李四/王五/赵六/钱七、技能版本）均为真实感演示数据，可直接用于联调占位。

## v0.3 修订（2026-11-22 需求澄清，以此为准）

产品模型改为「会话优先」：主工作区是 DSH 会话 + skills，UI 只负责看状态和三个写入口。

**新增页面**
- `onboarding.html` / `onboarding-folder.html` / `onboarding-confirm.html`：首次使用三步向导（身份/平台多选 + 当前身份 → 顶级文件夹 → 确认）。登录成功后未配置则进入；设置页可再改。

**三个写入口**
- 创建迭代（弹窗）、创建需求（弹窗，只填名称；点创建后后台 建文件夹→建会话→打开会话/Design Studio，带「创建中/创建失败」态，落到会话/Design Studio）、创建会话（如需补充设计/评审会话）。
- 其余写操作（评审/排期/范围调整、设计认领/指派/开始、需求提交/变更、设计交付、技能安装启停）全部由会话里的 skill 完成，UI 不做表单。

**已删除 / 改写**
- 删除设计模式三态（不需要/并行/设计先行）及 badge、designMode 选择器；需求卡只保留设计状态（未开始/设计中/已交付/设计已更新/无需设计）。
- 删除迭代详情独立「设计任务」区块（保留活动日志/范围摘要）。
- 右栏改为明确标注「DSH Design Studio · 复用，插件不重画」，插件只加需求编号/标题/状态/当前版本 + 「在会话中提交」入口（`requirement-workbench.html`、`design-workbench.html` 均为此占位）。

**平台模型（可配置「组 + 团队」）**
- 不再写死 8 列。平台分「服务端组 / 前端·客户端组 / 中台组(可选)」，组下是具体平台/团队（交易/商品/用户服务端、Web/小程序/iOS/Android/鸿蒙…）。
- 需求只选具体平台；矩阵与各端卡片按需求实际涉及的平台、按组动态渲染，不涉及折叠成一行（见 `requirement-full.html` 的「不涉及：安卓、鸿蒙」）。
- 设置新增「平台配置（管理员）」：新增/改名/排序/归档。

**各端卡片（`requirement-full.html`）**
- 按组分区，每端一张卡：平台组·平台名 + 状态 + 负责人 + 计划/实际时间 + 关键产物（服务端接口文档版本+就绪+commits+下游；前端设计版本+接口就绪+目标端+commits；测试用例/Bug/提测环境）+ 依赖阻塞 + 最近更新 + 「进入会话」。不涉及折叠一行。

**其他保留修正**
- 需求全量页：需求版本历史（v3 最新）与原型版本历史（v2 最新）分开，补「需求日志」。
- 顶部导航统一（含「通知」）；通知模拟器补「需求提交」；登录 Mock 用户补 钱七(测试)、周九(多平台)。
- 「查看全部 12 个需求」不再链到单个需求全量页。
- 技能库最小版：审核/上传/角色包统一「Phase 2 预览」灰置，无可点的 Phase 2 入口（`skill-admin.html` 为预览）。
- 全局「当前身份」置于迭代列表顶栏；按权限隐藏/禁用创建入口（示例）。
