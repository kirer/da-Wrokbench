## 一、浅色主题（对应第 15 条）

**现状**：工作台画布（`.dsh-wb-design`）用的是写死的一套深色变量（`--bg:#151517`、`--surface:#232326`、`--text/#fff` 之类），不跟 DSH 的深/浅色走；后来新增的页面已经改用宿主语义变量 `--dsw-alias-*`。于是现在是「新旧两套并存」，浅色下画布还是黑的。

### 方案 A（推荐）：画布全部改用宿主语义变量，自动跟随深/浅色
把画布那套死变量映射到 DSH 的 token，深浅色由宿主自动决定，**不用新增任何配色**，也和原生聊天界面完全一致。

| 画布变量 | 映射到宿主变量 |
|---|---|
| `--bg` | `--dsw-alias-bg-base` |
| `--surface` / `--panel` | `--dsw-alias-bg-layer-1` / `-2` |
| `--text` | `--dsw-alias-label-primary` |
| `--text-2` / `--text-3` | `--dsw-alias-label-secondary` / `-tertiary` |
| `--line` / `--line-2` | `--dsw-alias-border-l1` / `-l2` |
| `--primary` | `--dsw-alias-brand-primary` |
| 状态色（warn/success/error） | `--dsw-alias-state-*` |

- 好处：深浅色自动切换、零新配色、不会「AI 味」。
- 风险：少数自定义状态色要逐个对齐，我会一处一处改、边改边看。

### 方案 B：保留自定义配色，另补一套浅色值
保持现在的深色不变，浅色单独给一组值（示例，可再调）：

| 用途 | 浅色值 |
|---|---|
| 背景 | `#FFFFFF` |
| 卡片/层1 | `#F7F7F8` |
| 层2 | `#EFEFF1` |
| 边框 | `#E6E6E9` |
| 主文字 | `#1A1A1C` |
| 次文字 | `#5C5C66` |
| 强调 | `#3B5BDB` |

- 好处：完全按你的喜好定。
- 风险：每个颜色都要你过目，容易返工。

**请回复「A」或「B」**（或直接说想要的感觉/参考），我再动这块。

## 二、前端拆分与构建（对应 25 / 26 / 27）

**现状**：`plugin/client.js` 单文件 8500+ 行 / 550KB，样式、SVG 图标、Store、Markdown、弹窗、全部页面堆在一起；`DESIGN_CSS` 里很多重复选择器。

**计划**：引入 **esbuild**（零配置、构建快），源码拆分、打包后仍输出**单个 `client.js`**，宿主加载方式不变、零停机风险。

```
plugin/src/
  styles/      base.css, design.css, components.css（去重后）
  icons/       icons.js（按需 symbol 组件）
  stores/      workbench.js, requirement.js, auth.js
  components/  dialogs/, cards/, layout/
  pages/       iterations.js, requirement.js, skills.js, settings.js
  main.js      组装入口
plugin/client.js  ← esbuild 产物（保持单文件、保持 exports 不变）
```

- #26 类型：源码用 JSDoc 标注，构建期跑 `tsc --noEmit` 做静态检查（不改运行产物）。
- #27 去重：抽公共 CSS、统一前缀，消除 `.radio-card`/`.dsh-wb-btn` 等重复定义。
- 验证：每一步都跑 `node --check` + `host-bff.mjs`（62 项），产物与旧版行为对比。
- 回滚：保留拆分前的 `client.js.bak`，出问题一键还原。

**这需要引入 `esbuild` 作为构建依赖**（只在打包时用，不影响运行时）。你同意的话我就搭这套骨架，然后把代码一块块搬过去。
