# 剩余受限项说明（已尽力，受客观条件限制）

下面几项属于「优化建议」里最后没做到位的地方，均为外部依赖或超出插件范围导致，已给出可执行的后续路径。

## 1. Postgres 加密连接（第 59 条剩余）
- 现状：Postgres 后端连接仍是明文（tokio-postgres 的 NoTls）。
- 原因：接 TLS 需要 `tokio-postgres-rustls`（或等价适配器）+ 一个支持 SSL 的 Postgres 才能验证；本机 cargo 缓存里没有该适配器 crate、离线无法安装，且不能在无测试环境的情况下盲写并声称完成加密（安全代码必须验证）。
- 后续：在有网络的环境执行 `cargo add tokio-postgres-rustls rustls webpki-roots`，在 `pg.rs` 的 `open()` 按 `WORKBENCH_PG_TLS=1` 选择 `MakeTlsConnect`，用启用 SSL 的 Postgres 做一次回归即可。

## 2. 桌面端安全存储（第 33 条剩余）
- 现状：网页端已改为「令牌只放内存、优先用 Cookie」；桌面端（dsh-app://）因 Cookie 不持久，仍把令牌存本地。
- 原因：真正安全的做法要用 Electron/DSH 主进程的 safeStorage 加密存储，本插件跑在渲染层、拿不到主进程能力，超出插件范围。
- 后续：由 DSH 宿主提供「安全存取凭据」的接口，插件改为调用之。

## 3. 技能「按请求隔离」（第 37 条剩余）
- 现状：团队技能缓存已按登录 token 分桶，多用户不再互相覆盖数据。
- 原因：DSH 的技能 provider 接口是「进程级」的（list/get 无请求上下文），无法做到严格按每次请求的用户隔离；要彻底解决需宿主在技能接口里传入请求身份。
- 后续：等 DSH 技能接口支持请求上下文后，按请求取对应分桶即可。
