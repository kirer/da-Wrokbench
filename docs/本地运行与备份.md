## 1. DSH 插件：打包与安装

### 1.1 代码结构

- `plugin/package.json`：包清单，声明 `dsh.bundle.patch = ./cordis.patch.yml`、`main = ./index.js`。
- `plugin/index.js`：Host 插件入口，装配 BFF 路由、工具、技能、命令和设计画布。
- `plugin/src/*.js`：浏览器端源码分片；`plugin/build.mjs` 把它们拼成单文件 `client.js`。
- `plugin/client.js`、`client.canvas.js`：已构建好的浏览器端产物，`npm pack` 直接打包它们。
- `plugin/lib/*.js`：Host 端按职责拆分的实现。
- `plugin/vendor/canvas/`：设计画布宿主端及 `ui-design` 技能。

### 1.2 本机打包

```powershell
cd E:\da-Wrokbench\plugin

# 只有改过 src/ 后才需要重新拼 client.js；不改前端可跳过
node .\build.mjs

# Windows 上不要用 npm run check：它的脚本是 bash 的 for 循环，会报 "f was unexpected at this time"
node --check index.js
node --check client.js
node --check client.canvas.js
Get-ChildItem .\lib\*.js | ForEach-Object { node --check $_.FullName }

npm pack --pack-destination ..\dist
```

产物：`E:\da-Wrokbench\dist\dsh-workbench-0.1.10.tgz`。版本号来自 `plugin/package.json`，升级版本后再打包会得到新文件名。

### 1.3 安装到开发用 Web profile（推荐先用这个验收）

`workbench-poc` 是 README 约定的开发 profile。当前它的 `dsh-workbench` 依赖指向 `E:\da-Wrokbench\poc`，而该目录没有 `package.json`，所以 `dsh --profile workbench-poc --dump-config` 会报：

```text
dsh: skipping profile bundle "dsh-workbench": Error: ... cannot resolve profile bundle ...
```

如果 profile 里只有 `@deepseek-ai/dsh-base`、没有 `@deepseek-ai/dsh-web-app`，说明它是 `dsh plugin add` 自动建出来的 base-only profile，启动后不会监听端口。先备份旧目录，从 `web` 模板重建，再装插件：

```powershell
$prof = "$env:DSH_HOME\profiles\workbench-poc"
$bak = "$prof.bak-$(Get-Date -Format 'yyyyMMdd-HHmmss')"
if (Test-Path $prof) { Move-Item $prof $bak }
dsh --profile workbench-poc --from-default-profile web --dump-config > $null
dsh plugin --profile workbench-poc add E:\da-Wrokbench\plugin
dsh --profile workbench-poc --dump-config | Select-String dsh-workbench
```

如果 profile 已有 `@deepseek-ai/dsh-web-app`，只执行最后两条 `plugin add` / `dump-config` 即可。安装完成后依赖应显示为 `link:E:/da-Wrokbench/plugin`。

启动 Web 版：

```powershell
$env:WORKBENCH_SERVER_URL = 'http://127.0.0.1:3210'
$env:DSH_WORKBENCH_BASE = 'E:\da-Wrokbench\runtime\workbench'
dsh --profile workbench-poc --no-open --port 3199
```

打开终端输出的带 token URL，左侧出现「研发工作台」。

### 1.4 安装到桌面端 profile

桌面端固定加载 `~\.dsh\profiles\desktop`。安装前先完全退出 DeepSeek Harness（托盘退出），否则 Windows 可能锁住 `node_modules`：

```powershell
dsh plugin --profile desktop add E:\da-Wrokbench\dist\dsh-workbench-0.1.10.tgz
```

当前桌面 profile 有两个遗留状态需要处理：

1. `node_modules\dsh-workbench` 是指向 `E:\da-Wrokbench\poc` 的 junction，而 `poc` 没有 `package.json`；上面的 `plugin add` 会把它替换成 tgz 依赖。
2. `~\.dsh\profiles\desktop\cordis.patch.yml` 末尾有：

```yaml
- id: dsh-workbench
  disabled: true
```

把它改成 `disabled: false`（或删除这两行），否则插件虽然安装也不会挂载。改完重启桌面端，在「插件」页确认 `dsh-workbench` 行已启用。

## 2. 启动 Rust 团队服务端

### 2.1 本机工具链注意

本机 `rustc` 默认是 `x86_64-pc-windows-msvc`，但没有安装 Visual Studio Build Tools，`cargo build` 会报：

```text
error: linker `link.exe` not found
```

本机已安装 `stable-x86_64-pc-windows-gnu`，且 `C:\msys64\ucrt64\bin\gcc.exe` 可用。实测可用的构建命令：

```powershell
cd E:\da-Wrokbench\server
cargo +stable-x86_64-pc-windows-gnu build
```

也可以直接把 GNU 设为默认工具链（可选）：

```powershell
rustup default stable-x86_64-pc-windows-gnu
```

### 2.2 前台启动（SQLite）

```powershell
cd E:\da-Wrokbench\server
cargo +stable-x86_64-pc-windows-gnu run
```

默认配置：

- 监听：`127.0.0.1:3210`（`PORT` 可改）
- 数据库：`./data/workbench.db`，即 `E:\da-Wrokbench\server\data\workbench.db`
- 认证：`development` 下默认 `mock`，登录页可直接点种子员工

健康检查：

```powershell
Invoke-WebRequest http://127.0.0.1:3210/health -UseBasicParsing | Select-Object -ExpandProperty Content
```

实测返回：

```json
{"database":"sqlite","ok":true,"provider":"mock","serverTime":"...","service":"dsh-workbench-server","version":"0.1.0"}
```

用构建产物在后台跑时，务必显式指定绝对数据库路径，否则 `./data` 会相对于当前工作目录变化：

```powershell

$env:PORT = '3210'
Start-Process -FilePath 'E:\da-Wrokbench\server\target\debug\dsh-workbench-server.exe' `
  -WorkingDirectory 'E:\da-Wrokbench\server' -WindowStyle Hidden
```

### 2.3 Docker + Postgres

根目录先准备 `.env`（不要提交）：

```powershell
Copy-Item .env.example .env
# 填 POSTGRES_PASSWORD / WORKBENCH_AUTH_SECRET / WORKBENCH_INTERNAL_TOKEN
# 可用 openssl rand -hex 32（Git Bash）或 PowerShell 生成随机值

docker compose ps

```

`docker-compose.yml` 只把端口发布到 `127.0.0.1:3210`，Postgres 数据在命名卷 `workbench-pg` 中。停服务用 `docker compose down`（保留卷）；要连数据库一起删才加 `-v`。

## 3. 数据库：初始化、种子与备份

### 3.1 SQLite（默认，零配置）

服务端启动时 `db::open()` 会自动：

1. 创建数据库父目录；
2. 打开 SQLite，设置 `journal_mode=WAL`、`foreign_keys=ON`、`busy_timeout=5000`；
3. `init_schema()` 建表并补齐 `hash` 列；
4. 空库且处于开发环境时写入种子数据（8 名员工、1 个项目、2 个迭代、9 个需求——已实测）。

表：`users`、`platform_groups`、`platforms`、`projects`、`iterations`、`requirements`、`skills`、`events`、`notifications`、`artifact_contents`、`webhook_deliveries`、`revoked_tokens`、`workbench_meta`。

生产环境默认不写演示数据；需要演示数据时显式设置 `WORKBENCH_SEED_DEMO=1`。

SQLite 在线备份（不要直接复制 WAL 库）：

```powershell
sqlite3 "E:\da-Wrokbench\server\data\workbench.db" ".backup 'E:\da-Wrokbench\server\data\workbench-backup-20261128.db'"
sqlite3 "E:\da-Wrokbench\server\data\workbench-backup-20261128.db" "pragma integrity_check;"
```

仓库里的 `tools/workbench-db-backup.sh` 是 bash + sqlite3 版本（默认备份到 `~/.dsh/backups/workbench-db`，保留 14 份），在 Git Bash/WSL 中可用。

### 3.2 Postgres（`DATABASE_URL`）

只要设置了 `DATABASE_URL`，服务端就走 Postgres，不再用 `DATABASE_PATH`。`pg::init()` 自动建表、补 `hash` 列、迁移旧的 `workbench_state` 单行 JSONB，并在空库时按 `WORKBENCH_SEED_DEMO` 决定是否种子。

备份：

```powershell
docker exec dsh-workbench-postgres pg_dump -U workbench -d workbench -Fc -f /tmp/workbench.dump
docker cp dsh-workbench-postgres:/tmp/workbench.dump .\dist\workbench.dump
```

恢复：

```powershell
docker cp .\dist\workbench.dump dsh-workbench-postgres:/tmp/workbench.dump
docker exec -i dsh-workbench-postgres pg_restore -U workbench -d workbench --clean --if-exists /tmp/workbench.dump
```

### 4.2 Windows 备份脚本

仓库原有的 `tools/dsh-session-backup.sh` 是 macOS 版：`/Applications/DeepSeek Harness.app`、`pgrep`、`osascript`、`date -r` 在 Windows 不可用。已新增 Windows 版 `tools/dsh-session-backup.ps1`，备份内容与 bash 版一致，另支持 `list` / `restore`。

> 该脚本保存为 **UTF-8 with BOM**：Windows PowerShell 5.1 直接输入脚本路径运行时，没有 BOM 的 UTF-8 会被按 ANSI/GBK 解析，中文变成 `澶囦唤` 之类的乱码并触发语法错误。以后若用编辑器另存，请保留 BOM，或改用 `pwsh -NoProfile -File` 运行。

```powershell
cd E:\da-Wrokbench

# 备份（默认标签 manual，可自定义）
pwsh -NoProfile -File .\tools\dsh-session-backup.ps1 backup manual

# 查看备份
pwsh -NoProfile -File .\tools\dsh-session-backup.ps1 list

# 恢复（必须先退出 DeepSeek Harness；会先自动做 pre-restore 备份）
pwsh -NoProfile -File .\tools\dsh-session-backup.ps1 restore "C:\Users\EDY\.dsh-session-backups\dsh-sessions-20261128-153018-manual.tar.gz" -Yes
```

环境变量可覆盖默认目录：`DSH_HOME`、`BACKUP_DIR`、`KEEP`（默认保留 10 份）。

原 macOS 脚本 `tools/dsh-session-backup.sh` 的执行顺序：

| 动作 | 是否先关 DSH | 实际顺序 |
| --- | --- | --- |
| `backup` | 否 | 直接打包当前 `~/.dsh`，DSH 可以开着 |
| `restore` | 是 | `require_app_closed`（退出 DSH）→ `cmd_backup pre-restore` → 解包覆盖 |
| `clear-workbench-sessions` | 是 | `require_app_closed` → `cmd_backup pre-clear` → 删除该工作区会话 |
| `clear-all-sessions` | 是 | `require_app_closed` → `cmd_backup pre-clear-all` → 清空全部会话 |

所以破坏性操作内部是 **先关闭 DSH → 再做安全备份 → 最后恢复/清除**；`backup` 子命令本身不关 DSH。`tools/reset-workbench-test-data.sh` 是另一套：它按设计 **不做备份**，直接退出 DSH 并删除数据库、本机目录和会话；要留档需先手动执行 `backup`。

本次已实测生成一份当前会话备份：

```text
C:\Users\EDY\.dsh-session-backups\dsh-sessions-20261128-153018-manual.tar.gz
93.61 MB，251 个条目，包含 storages/workspace.json 和 sessions/
```

### 4.3 一键重置 / 一键恢复（Windows）

新增了三个入口，底层都是 `tools/dsh-session-manager.ps1`：

| 入口 | 作用 |
| --- | --- |
| `tools\dsh-session-manager.cmd` | 菜单：备份 / 一键重置 / 一键恢复 / 查看备份 |
| `tools\dsh-session-reset.cmd` | 一键重置：备份 → 退出 DSH → 清空全部会话 → 打开 DSH |
| `tools\dsh-session-restore.cmd` | 一键恢复：备份当前 → 退出 DSH → 选择备份恢复 → 打开 DSH |

双击 `.cmd` 即可运行；脚本会先让你确认一次，然后按顺序执行。**菜单 1 只是备份，不会退出 DSH**；完整流程请选菜单 2，或直接双击 `tools\dsh-session-reset.cmd`。重置默认清空**全部 DSH 会话**；只清工作台会话时用菜单选 `W`，或命令行：

```powershell
# 全部会话重置
pwsh -NoProfile -File tools\dsh-session-manager.ps1 reset -Scope All

# 只清 WorkbenchBase（默认 runtime\workbench）下的会话
pwsh -NoProfile -File tools\dsh-session-manager.ps1 reset -Scope Workbench

# 恢复最新备份
pwsh -NoProfile -File tools\dsh-session-manager.ps1 restore -Yes

# 恢复指定备份
pwsh -NoProfile -File tools\dsh-session-manager.ps1 restore -Archive "C:\Users\EDY\.dsh-session-backups\dsh-sessions-20261128-153018-manual.tar.gz" -Yes

# 只看流程、不实际改数据
pwsh -NoProfile -File tools\dsh-session-manager.ps1 reset -Scope All -Yes -DryRun
```

注意：

- 重置/恢复会退出 DeepSeek Harness。请从资源管理器双击 `.cmd`，或在独立 PowerShell 窗口运行；从 DSH 内部终端运行会检测到并中止，因为退出 DSH 会把脚本自身一起终止。
- `-NoRelaunch` 只执行到清除/恢复为止，不重新打开 DSH。
- 恢复流程会先备份当前状态，再做 `pre-restore`；备份文件格式与 `dsh-session-backup.ps1` 互通。

### 4.4 备份范围说明

该脚本只备份 DSH 会话状态，不含 `settings.yaml`、`.credentials.yaml`、插件目录和模型凭据。要迁移整套 DSH 配置，另行复制：

- `C:\Users\EDY\.dsh\settings.yaml`
- `C:\Users\EDY\.dsh\.credentials.yaml`（敏感，单独保管）
- `C:\Users\EDY\.dsh\profiles\desktop\`（插件清单与用户 patch）

## 5. 本机常见坑

1. **`npm run check` 在 Windows 失败**：`plugin/package.json` 的 `check` 脚本用了 bash 的 `for f in lib/*.js`；改用上面的逐文件 `node --check` 命令。
2. **`cargo build` 找不到 `link.exe`**：默认 MSVC 工具链缺少 VS Build Tools；用 `cargo +stable-x86_64-pc-windows-gnu build`。
3. **桌面端 `dsh-workbench` 指向 `poc`**：`E:\da-Wrokbench\poc` 没有 `package.json`，是旧布局残留；安装 `plugin` 或 `dist\*.tgz` 会替换该 junction。
4. **桌面端插件被禁用**：`~\.dsh\profiles\desktop\cordis.patch.yml` 中有 `- id: dsh-workbench / disabled: true`，安装后要改为 `false`。
5. **服务端数据库路径随 cwd 变化**：`DATABASE_PATH` 默认是 `./data/workbench.db`；从仓库根启动二进制会写到根目录 `data\`，脚本中应使用绝对路径。
6. **端口冲突**：插件默认连 `http://127.0.0.1:3210`；换端口时同时设置服务端 `PORT` 和插件 `WORKBENCH_SERVER_URL`。
