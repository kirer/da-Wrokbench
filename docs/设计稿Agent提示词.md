# 角色

你是一位资深 B 端产品设计师，擅长高信息密度的研发协作工具。请为「DSH 部门研发工作台」设计一套高保真 UI，并输出可直接交给前端实现的设计系统与页面稿。

> 本提示词已按 2026-11-22 需求澄清更新到 v0.3。若与旧稿冲突，以本文和《设计修订说明与提示词.md》为准；旧稿中的 `designMode`、设计先行、固定平台 8 列、评审/排期/范围表单均已废弃。

# 背景

- 产品是 DeepSeek Harness（DSH）的桌面插件。DSH 是一个 AI 工作台：最左是窄导航/会话列表，中间是会话或工作区，右侧是可折叠的上下文面板；整体是桌面应用，不是网页落地页。
- 使用者是互联网产品研发部门：负责人/项目经理、产品、设计、开发、测试。
- 第一版范围只做「需求 + 设计」：迭代 → 需求 → 评审/排期 → 设计（可选/默认并行）。开发、测试、封板只在信息架构里留入口，不做细稿。
- 服务端只存「已提交/已交付」的沉淀数据；会话全文、需求草稿、多个原型/设计草稿都在本地。界面要区分「草稿（仅本地）」「已提交」「已交付」。
- 钉钉登录第一版用 Mock：登录页要能选测试用户，并有 Mock 模式提示；正式钉钉界面保持一致。

# 最重要的交互模型

1. **主工作区是 DSH 会话 + skills，不是表单中心。** UI 主要负责「看状态」和「进入会话」。
2. **UI 的写入口只保留三个：**
   - 创建迭代（负责人/项目经理）；
   - 创建需求（**只输入需求名称**；后台创建需求文件夹 + 会话，并打开会话/Design Studio）；
   - 创建会话（从需求/迭代选择会话类型；如果创建需求已自动建会话，这个入口只用于补充设计/评审等额外会话）。
3. **其他写操作全部由会话里的 skill 完成：** 评审通过/打回、排期、范围调整、设计认领/指派/开始、需求提交/变更、设计交付、技能安装/启停等。UI 不再做这些表单和弹窗。
4. **右栏 = DSH Design Studio。** 需求/设计右栏基于 Design Studio 改造，外观和交互以 Design Studio 为准；本插件不重新设计画布，只加需求上下文（编号/标题/状态）和「在会话中提交」入口。开发/测试/Bug 工作台只留信息架构入口。
5. **设计任务不是独立 UI 区块。** 需求卡只显示设计状态（无需设计/待认领/设计中/已交付/设计已更新）；认领、指派、开始设计都由 skill 在会话里完成。
6. **不做设计模式三态。** 没有 `不需要 / 并行 / 设计先行` 的选择器和 badge。设计默认是可选的并行轨道；设计晚于开发就标「设计已更新」；确实要等设计时，由 skill 把开发任务标成「等待设计」，UI 只显示这个状态。
7. **平台不要写死。** 中台不一定有；服务端/前端也可能有多个团队。平台是「平台组 + 平台/团队」的可配置列表，需求和矩阵按实际涉及的平台动态渲染。

# 设计目标

- 专业、克制、可扫读，像 Linear / Height / Notion / GitHub Projects 的内部工具，不是营销页。
- 信息密度偏高但不拥挤；用表格、分割线、紧凑工具栏、状态 chip 组织信息。
- 左栏是主页面，中间是会话，右侧是当前对象的上下文；右栏不能抢主会话的注意力。
- 中文界面，浅色/深色两套；桌面端 1440×900，右栏 360–420px。
- 视觉方向：冷净的工程感。中性色为主，低饱和蓝/绿作主色；编号、版本、代码用等宽字体；圆角 6–8px；细边框；不使用大面积渐变、玻璃拟态、超大圆角、emoji 图标、Hero 区。

# 设计系统（先输出）

请先给出 tokens 与组件规范，再画页面：

- 颜色：背景/表面/边框/文字（主/次/弱）、主色、状态色（未开始、进行中、已完成、阻塞、不涉及、仅本地草稿）。
- 字体：中文界面字体、字号层级、行高；编号/版本用等宽。
- 间距、圆角、阴影、分割线。
- 组件：按钮（主/次/危险/文字）、输入框、下拉、日期、表格、卡片、状态 chip、阶段矩阵、平台卡、头像/指派、标签页、右栏面板、空状态、Toast、确认弹窗、版本 diff、文件选择器。
- 状态 chip 不能只靠颜色区分，要带文字或图标，兼顾色盲。
- 平台卡是本次新增重点：平台组 · 平台/团队、状态、负责人、计划/实际时间、关键产物、依赖/阻塞、最近更新、「进入会话」。

# 信息架构

- 左侧栏：迭代列表、我的工作台、技能库、设置；底部显示当前身份和组织。
- 主页面：迭代列表、迭代详情、需求全量页、我的工作台、技能库、设置。
- 会话右栏：DSH Design Studio 需求上下文、DSH Design Studio 设计上下文；开发/测试/Bug 工作台只留入口。
- 通知中心 / Mock 通知模拟器。

# 核心对象与状态（用于界面表达）

- 迭代：编号（可改）、名称、负责人、阶段（需求与评审/设计/开发/测试/封板）及计划起止、状态（规划中/进行中/已封板）、需求范围。
- 平台配置：两级可配置。
  - `PlatformGroup`：服务端、中台、前端、客户端…（可增删改/排序；中台不一定有）。
  - `Platform`：交易服务端、商品服务端、用户服务端、Web、小程序、iOS、Android、鸿蒙…（挂在组下，可新增/改名/排序/归档）。
  - 示例：服务端组 3 个团队（交易/商品/用户）+ 前端组 2 个（Web/iOS）；测试是阶段，不是平台组；中台如需要可加一个组，不需要就不放。
  - 接口型平台组用 `supportsApiDoc` 标记；只有这类组显示接口文档/「接口已就绪」，不要按组名硬编码。
- 需求：编号（如 S11-001）、标题、总述、涉及平台（具体 Platform ID，不是固定枚举）、优先级、生命周期（创建中/待评审/已排期/进行中/待测试/测试中/已完成/已封板 + 异常）。
- 需求卡用「阶段矩阵」表达进度：需求、设计、该需求实际涉及的平台（按组分组）、测试，各自一个 chip（未开始/进行中/已完成/阻塞/不涉及）。
- 设计任务：无需设计/待认领/已指派/设计中/已交付/待修改/设计已更新；设计不是评审/排期的前置条件；认领/指派/开始设计由会话 skill 完成。
- 技能：Skill、SkillVersion、SkillPack、SkillInstall、SkillUsage、SkillReview；版本、适用角色/平台、状态（草稿/审核中/已发布/已废弃）、启用/停用、版本历史、diff、回滚、角色/平台技能包、个人上传（第一版只留入口）。

# 页面清单

## P0（必须出高保真）

1. **登录与首次使用**：钉钉/Mock 登录；首次使用独立 onboarding：选择职能 + 平台/团队（可多选）→ 选择当前身份 → 选择个人顶级文件夹；状态：未登录、登录中、失败、Mock 提示、权限不足、路径不可写。
2. **迭代列表**：迭代卡/表；字段：编号、名称、当前阶段、起止、负责人、需求数、进度、风险；筛选「我参与的/进行中/已封板」；新建迭代入口。
3. **迭代详情**：头部（编号/名称/负责人/状态/范围锁定）、阶段时间轴（设计轨道允许与需求/开发重叠）、需求卡片/列表（每行/每卡带按平台组分组的阶段矩阵）、设计状态汇总、日志抽屉、范围摘要；状态：无需求、设计未指派、设计未交付但开发继续、范围锁定。
   - 删除独立「设计卡片/设计任务」区块；删除范围调整表单（走会话 skill）。
   - 矩阵只渲染该需求涉及的平台；平台多时用「服务端 3」汇总 + 展开；不涉及平台折叠；必须有列头。
4. **新建需求**：弹窗只保留「需求名称」；点击创建后展示后台步骤（创建文件夹 → 创建会话 → 打开会话/Design Studio）的创建中/失败态；落地页是会话/Design Studio，不跳只读全量页。
5. **需求工作台（右栏）**：DSH Design Studio + 需求上下文：编号/标题/状态、当前版本、总述、原型、版本/日志；提交/变更走会话 skill；状态：草稿、已提交、变更中、服务端断开。
6. **需求全量页**：总述、原型、设计稿、设计组件、接口文档（预留）、按平台组分区的各端卡片、Bug（预留）、版本历史、日志；只展示已提交/交付版本；状态：无设计、设计未交付、设计已更新、历史版本。
   - 平台卡按组分区，不涉及的平台折叠成一行；每张卡含：平台组 · 平台/团队、状态、负责人、计划/实际时间、关键产物（服务端接口文档版本/就绪状态、commits/MR、下游依赖；前端设计版本/接口就绪/目标设备；测试用例/Bug/环境）、依赖/阻塞、最近更新、「进入会话」。
7. **设计工作台（右栏）**：DSH Design Studio + 上游需求摘要、原型、设计 brief、设计画布、设计系统/组件库入口、版本对比、提交设计；状态：未认领、设计中、已交付、需修改、设计已更新。删除「设计先行阻塞」；认领/指派/提交由会话 skill 完成。
8. **技能库（最小版）**：列表（按角色/平台筛选）、技能详情（描述、版本、changelog、内容预览、兼容性）、启用/停用、固定版本、版本历史；个人上传入口灰置/「Phase 2」提示。

## P1（可简化，但要有）

9. **技能上传/审核/角色包/统计**：上传向导、校验结果、预览、审核队列、diff、角色/平台技能包编辑、使用统计。
10. **我的工作台**：我的需求、我的设计任务、待办；空态、多身份。
11. **设置**：身份与平台/团队、顶级文件夹、平台配置（管理员）、认证模式（Mock/钉钉）、通知偏好、技能更新策略；Mock/正式切换提示。
12. **通知中心/模拟器**：指派、变更、提交、系统消息；空态、未读、Mock 通知。

# 交互与状态要求

- 每个页面至少给：默认态、空态、加载态、错误态、无权限态；关键操作给成功/失败提示。
- 设计默认并行必须在迭代详情和需求卡上看得懂：设计没出时，评审/排期仍可继续；只有明确等待设计时，对应开发任务显示「等待设计」；设计晚交付显示「设计已更新」。
- 草稿 vs 已提交 vs 已交付要有明确视觉区分；草稿标「仅本地」；不要用「仅本地」样式表示设计状态。
- 平台多时矩阵仍要可扫读：按组汇总、可展开、不涉及折叠、有列头。
- 所有写操作收在会话 skill 里：UI 只保留创建迭代/需求/会话，以及「进入会话」。
- 技能库要让用户一眼看懂：版本、适用角色/平台、状态、启用/停用；个人上传第一版灰置。
- Mock 模式要有提示，但不干扰主流程。
