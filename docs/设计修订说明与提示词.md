## 一、澄清后的交互模型

1. **主工作区是 DSH 会话 + skills。** UI 不是表单中心，主要负责「看状态」和「进入会话」。
2. **UI 的写入口只保留三个：**
   - 创建迭代（负责人/项目经理）；
   - 创建需求（只输入需求名称；后台创建需求文件夹 + 会话，并打开会话）；
   - 创建会话（从需求/迭代选择会话类型；如果创建需求已经自动建会话，这个入口只用于补充设计/评审等额外会话）。
3. **其他写操作全部由会话里的 skill 完成：** 评审通过/打回、排期、范围调整、设计认领/指派/开始、需求提交/变更、设计交付、技能安装/启停等。UI 不再做这些表单和弹窗。
4. **右栏 = DSH Design Studio 改造。** 外观和交互以 Design Studio 为准，不在本插件设计稿里重新发明。插件只在必要处加需求上下文（编号/标题/状态）和「在会话中提交」入口；具体等 Design Studio 的稿子定了再对齐。
5. **设计任务不是独立 UI 区块。** 需求卡只显示设计状态（未开始/设计中/已交付/设计已更新/无需设计）；认领、指派、开始设计都由 skill 在会话里完成。
6. **设计模式三态取消。** 不再有 `不需要 / 并行 / 设计先行` 的选择器和 badge。设计默认是可选的并行轨道；设计晚于开发就标「设计已更新」；确实要等设计时，由 skill 把开发任务标成「等待设计」，UI 只显示这个状态。
7. **首次使用补独立 onboarding：** 登录后先选职能/平台 + 当前身份，再选个人顶级文件夹，然后进入工作台。
8. **平台不要写死：** 中台不一定有；服务端/前端也可能有多个团队。平台改成「平台组 + 平台/团队」的可配置列表（示例：服务端组下的交易/商品/用户，前端组下的 Web/iOS/安卓/鸿蒙；中台组可选）。需求选择具体平台，矩阵和卡片按实际涉及的平台动态渲染。

## 三、设计 agent 还需要补/改的内容

### 1. 首次使用 onboarding（P0）

- 入口：`login.html` 登录成功后，如果用户未完成首次配置，进入 onboarding，不直接跳 `iterations.html`。
- Step 1 身份：职能多选（负责人/项目经理、产品、设计、开发、测试、管理员）、平台/团队多选（按服务端配置动态展示；示例：交易服务端、商品服务端、Web、iOS、Android、鸿蒙；中台如启用才显示）、当前身份单选。
- Step 2 文件夹：本地目录选择器；显示路径、可写徽标、磁盘空间；错误态（不存在/不可写/权限不足）；说明「会话、草稿、原型/设计草稿放这里，服务端只存提交/交付结果」。
- Step 3 确认：当前身份、文件夹、Mock/正式模式摘要；「进入工作台」；可返回修改。
- 状态：加载中、保存中、保存失败、路径无效、权限不足、Mock 提示。
- 完成后进入 `iterations.html`；设置页可再次修改。

### 2. 创建需求后的后台流程

- 弹窗只保留需求名称。
- 点击「创建需求」后，展示/暗示后台步骤：创建文件夹 → 创建会话 → 打开会话/Design Studio；不需要用户填字段。
- 状态：创建中、创建失败（文件夹不可写/会话创建失败，保留输入可重试）。
- 落地页改为会话/工作台，不要跳 `requirement-full.html`。

### 3. 创建会话入口（如果手动需要）

- 从需求卡或迭代详情进入；选择会话类型（需求/设计/评审等）→ 创建并打开 DSH 会话。
- 如果创建需求已自动建会话，稿子里注明「自动创建」，不额外加入口。
- 会话标题沿用 `[S11-001] 需求名` / `[S11-001] 需求名 · 设计`。

### 4. 去掉设计模式和设计任务区块

- 删除 `并行 / 设计先行 / 无需设计` 三态及对应 badge。
- 需求卡只保留设计状态；没有设计任务时显示「无需设计」。
- 迭代详情删除独立「设计任务」区块；如需要，保留一行设计状态汇总即可。
- 不要再用 `badge--local` 表示设计模式；`badge--local` 只表示「仅本地草稿/未同步」。

### 5. 右栏

- 明确写「此处为 DSH Design Studio，插件不改造」。
- 如果 Design Studio 的稿子还没定，保持现状占位即可，不要为了填满而发明新的右栏布局。
- 插件只在右栏加：需求编号/标题/状态、当前版本、「在会话中提交」入口；其他以 Design Studio 为准。

### 6. 上一版评审中仍然成立的修正

- 矩阵按需求实际涉及的平台动态渲染、按组分组；平台多时汇总 + 展开，不涉及折叠；不要只靠 tooltip。
- 全量页原型卡 `v2` 与版本历史 `v3 最新` 不一致；把需求版本历史和原型版本历史分开，补需求日志。
- 全局「当前身份」；按权限隐藏/禁用「创建迭代/需求/会话」。
- 技能库：第一版只做最小版，把审核/上传/角色包统一标「Phase 2 预览」或灰置，不要出现可点的 Phase 2 入口。
- 顶部导航统一（`my-workbench.html` 补「通知」）。
- 通知模拟器补「需求提交」；登录 Mock 用户补测试角色（钱七）和一个多平台用户。
- 「查看全部 12 个需求」不要链到单个需求的全量页。

### 7. 平台模型：可配置分组 + 平台

- 不要把平台写死成「服务端/中台/Web/iOS/Android/鸿蒙」8 列。
- 建议两层：
  - **PlatformGroup**：服务端、中台、前端、客户端（可增删改）。
  - **Platform**：交易服务端、商品服务端、用户服务端、Web、小程序、iOS、Android、鸿蒙…（挂在组下，可增删改/归档）。
- 需求 `platformScope[]` 存具体 Platform ID；身份也选具体 Platform；当前身份 = 职能 + 平台。
- 服务端组用 `supportsApiDoc` 标记（默认服务端组为 true）；矩阵里的「接口已就绪」和接口文档只给这类组，不靠组名硬编码。
- 管理端：设置里加「平台配置」（管理员），支持新增/改名/排序/归档；默认给一套种子，中台可以默认不放。
- 矩阵：只渲染该需求实际涉及的平台，按组分组；平台多时用「服务端 3」汇总 + 展开；不涉及的平台折叠成一行。
- 需求详情各端卡片：按组分区，每端一张卡；字段见下。

### 8. 各端卡片：从「负责人 + commit 数」丰富成可判断状态的卡

现在的问题：

- 只有负责人和 commit 数，信息太简略。
- 服务端没有接口文档版本/就绪状态/下游依赖；前端没有设计版本/接口依赖；测试没有用例/Bug 汇总。
- 「不涉及」的安卓/鸿蒙各占一张卡，浪费空间。
- 平铺 3 列，服务端/前端/客户端/测试混在一起，层级不清。

建议每张卡：

- **头部**：平台组 · 平台/团队名 + 状态 chip + 负责人 + 「进入会话」。
- **时间**：计划开始/结束、实际开始、预计完成；逾期/风险标识。
- **关键产物**：
  - 服务端：接口文档版本 + 就绪状态、commits/MR、下游前端依赖。
  - 前端/客户端：设计稿版本、接口就绪情况、目标设备/端、commits/MR。
  - 测试：用例进度、Bug 汇总（阻塞/待复测/已关闭）、提测环境。
- **依赖/阻塞**：等待设计/接口/其他平台；风险提示。
- **最近更新**：相对时间 + 最近事件。
- **动作**：只放「进入会话」（认领/提交/变更都由 skill 做；未指派写「待认领 · 进入会话认领」）。
- **不涉及**：折叠成一行「不涉及：安卓、鸿蒙（产品确认）」，可展开。
- **设计稿/原型**：在需求全量页的设计区补设计版本历史、设计组件、设计系统、进入设计会话；不要只放三张缩略图，也不要恢复独立设计任务区块。

## 四、给设计 agent 的提示词

### 提示词 A：首次使用 onboarding（复制即用）

```text
你是 DSH 研发工作台的设计 agent。现有 design/ 下已有一套高保真稿和设计系统（design-system.html、login.html、iterations.html、settings.html 等）。请补充「首次使用」独立步骤，保持现有视觉语言，不要重做设计系统。

背景：
- 产品是 DSH 桌面插件，1440×900，深色默认 / 浅色切换。
- 第一版只做「需求 + 设计」；大部分写操作在会话里由 skill 完成，UI 只做状态展示和入口。
- 登录已支持 Mock / 钉钉。登录成功后，如果用户还没配置身份和文件夹，进入首次使用向导，不直接跳迭代列表。
- 身份 = 职能（负责人/项目经理、产品、设计、开发、测试、管理员）+ 开发平台（按服务端配置动态展示；示例：交易服务端、商品服务端、Web、iOS、Android、鸿蒙；中台如启用则显示），可多选，权限取并集；需要选一个「当前身份」。
- 顶级文件夹只存本地路径，不上传服务端；要显示路径、可写校验、空间和失败态。

要补的内容：
1. 新增 onboarding.html（或 onboarding-identity.html + onboarding-folder.html）：
   - Step 1 身份：职能多选、开发平台多选、当前身份单选；说明「权限取并集，可随时在设置里改」。
   - Step 2 文件夹：本地目录选择器；显示路径、可写徽标、磁盘空间；错误态（不存在/不可写/权限不足）；说明「会话、草稿、原型/设计草稿放这里，服务端只存提交/交付结果」。
   - Step 3 确认：摘要（当前身份、文件夹、Mock/正式模式）；「进入工作台」；可返回修改。
2. 状态：加载中、保存中、保存失败、路径无效、权限不足、Mock 提示；成功后进入 iterations.html。
3. 入口：login.html 的「以…身份进入」在首次使用时跳到 onboarding；完成后跳 iterations.html；设置页可再次修改。
4. 交互：复用 settings.html 的 .ptog、路径框、按钮；主按钮蓝底白字；不要发明新组件。
5. 输出：新增 HTML，更新 login.html 链接和 README 页面表；给出默认态和失败态；不要改 DSH 原生左栏/会话区；右栏如出现，保持 Design Studio 引用，不重新设计。
```

```text
9. 输出：更新相关 HTML、README；列出改动清单；不要改 DSH 原生左栏/会话区。
```

### 提示词 D：平台矩阵与各端卡片（复制即用）

```text
请只改「需求全量页」的各端卡片和「迭代详情/需求卡」的阶段矩阵，不改其他页面，保持现有设计系统。

请做：
1. 设计稿里用一个示例需求展示：服务端 3 个团队（交易/商品/用户）+ 前端 2 个（Web/iOS）+ 测试阶段；中台如需要可加一个组，不需要就不放。
```
