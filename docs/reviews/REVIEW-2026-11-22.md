# DSH 研发工作台 · 代码与 UI/UX 审查报告

日期：2026-11-22
范围：`poc/index.js`（DSH host BFF）、`poc/client.js`（右侧栏 UI）、`poc/server/`（Rust 团队服务端）、`poc/docker-compose.yml`、`deploy/gitlab/`、测试脚本与文档。
方法：5 条审查线并行，每条线 10 轮，共 50 轮；每轮聚焦一个可验证的攻击面或交互路径，产出可定位到文件/函数的建议。最终合并去重为 120 条建议（S001–S120），按 P0–P3 分级，逐条给出修复状态。

## 分级口径

- **P0**：可导致越权、默认部署被接管、存储型 XSS 或核心流程不可恢复。
- **P1**：高概率数据错误、权限绕过、关键状态机死锁、明显不可用。
- **P2**：边界条件、并发竞态、错误处理、可访问性与可维护性问题。
- **P3**：文案、样式、体验细节、测试与文档改进。

## 仍建议在正式上线前完成

1. **令牌生命周期**：JWT 吊销表或短 TTL + 刷新令牌，退出登录立即失效。
2. **限流与审计**：登录、Mock 登录、Webhook 增加速率限制与失败告警。
3. **网络隔离**：反向代理 + HTTPS + mTLS；不要把 Compose 文件直接用于生产。
4. **数据演进**：状态拆表/增量 API；Postgres 启用 TLS；SQLite 仅限单机 POC。
5. **工具身份能力**：用短期 capability 取代“会话归属映射”作为工具执行凭证。
